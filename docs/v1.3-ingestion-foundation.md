# V1.3.1 ingestion foundation

This milestone provides an offline collection and evidence layer shared by future creator and business intelligence work. It adds no live provider, ranking formula, market inference, dashboard feature or automated publishing. V1.2's `ContentPost`, source adapters, pipeline, generation, quality checks and three export formats remain unchanged. The new SQLite database is opt-in and is not read by the dashboard.

## Modules

| Module under `src/trendscout/ingestion/` | Responsibility |
| --- | --- |
| `models.py` | Validated canonical records, result consistency and per-source retention configuration. |
| `base.py` | `IngestionSource` protocol and curated `CollectionError` codes/messages. |
| `synthetic.py` | Explicit synthetic fixture adapter with an injectable clock and at most three records. |
| `schema.py` | SQLite schema version and initial migration statements. |
| `repository.py` | Atomic persistence, idempotent retries, reads and expiration cleanup. |
| `demo.py` | Disposable end-to-end demonstration without keys or network access. |

## Canonical contracts

- **`ContentItem`** identifies content by `(platform, external_id)`. The platform is a lowercase namespace, not an adapter name. Native external IDs retain their original case and text; blank IDs are invalid. `item_id` is a deterministic UUID5 derived from the JSON-encoded pair, shared across sources. Each record separately names its collecting `source_id`, explicit attribution, provenance (`synthetic`, `live`, `unknown`) and content type. Title, description, creator, community, publication time and public HTTP(S) URL are optional. URLs containing embedded username/password credentials are rejected.
- **`NativeMetrics`** stores optional nonnegative integer counters under provider-native names, with an aware `observed_at`. A missing observation is `None`; an absent or null counter is unavailable. An explicit zero remains zero. Negative, fractional, boolean, string and out-of-range counters are rejected. Different platforms' counters are not normalized or treated as comparable scores. Signed/rate metrics need a future explicit contract; do not clamp them to zero.
- **`CollectionRequest`** contains source identity, a bounded nonblank query and an integer limit of 1–100. Query text is used in memory and is not persisted.
- **`CollectionRun`** records UUID, source, provenance, start/completion times, requested limit, accepted/rejected counts, status and safe error codes. A complete run may legitimately return fewer items than requested. Partial/failed runs require error codes; complete runs cannot hide rejected records. Failed runs contain no accepted items.
- **`CollectionResult`** binds the run to an immutable tuple of accepted records. Counts must match, identities must be unique within a batch, and each item's source, provenance and collection interval must match the run. Partial batches can retain their validated accepted records; rejected payloads are not retained.

All supplied timestamps must be timezone-aware and are normalized to UTC. Publication time may be unavailable and is not inferred from collection time. Observation time cannot follow item collection. Source expiration must follow the corresponding collection/observation. Models forbid unknown fields, including arbitrary raw-response or credential fields. The persistence boundary revalidates models, including nested records, to prevent bypass through unchecked construction or mutation.

## Adapter development

Implement the new `IngestionSource` protocol, independently of legacy `sources.base.ContentSource`:

```python
from trendscout.ingestion.models import CollectionRequest
from trendscout.ingestion.synthetic import SyntheticSource

source = SyntheticSource()
request = CollectionRequest(source_id=source.source_id, query="offline example", limit=3)
result = source.collect(request)
```

Adapters must reject requests for another source, honor the limit, identify synthetic data explicitly, normalize provider data, and report rejections through an explicit partial result. Use stable platform namespaces and native IDs, consistent UTC collection timestamps, and a new run UUID for a new collection. Reuse a run UUID only for delivery retries of the exact same result. Deduplicate before building a result. Transport/pagination/retry behavior belongs in each future provider adapter and must remain bounded. Do not silently substitute demo records after a live failure.

`CollectionError` exposes only curated `wrong_source`, `access_denied`, `rate_limited`, `unavailable` and `invalid_response` messages. Translate provider failures to these codes; never include tokens, response bodies or provider exception text. Result error codes are short machine identifiers, not free-form diagnostics. Strip unnecessary fields before constructing records, use public attribution URLs without signed credentials, and never copy authentication material into titles, descriptions or URLs. Model validation cannot detect every secret inside arbitrary text.

## SQLite schema and transactions

| Table | Data and keys |
| --- | --- |
| `content_items` | Stable internal ID and unique `(platform, external_id)` identity. |
| `item_records` | Latest normalized metadata for each `(item_id, source_id)`, collection time and effective expiration. Validated metadata is stored as JSON, excluding metrics. |
| `collection_runs` | Run UUID, indexed source/completion time, validated operational run JSON and a retry fingerprint. No query, title or response body. |
| `run_items` | Unique `(run_id, item_id)` association, collecting source, collection time and expiration. |
| `metric_observations` | Native values, observation/expiration times, unique `(item_id, source_id, observed_at)`. |

Source-specific metadata prevents one source's retention policy from prolonging another source's retained fields. Foreign keys and cascading deletion bind metadata, observations and associations to their parents. Expiration, source/time and association indexes support cleanup and reads. All user values use SQL parameters; interpolated table names come only from a fixed schema tuple.

Every save and purge uses an explicit `BEGIN IMMEDIATE` transaction. SQL errors or observation conflicts roll back the whole operation, including run insertion and metadata updates. Concurrent writers use SQLite's bounded connection timeout. Schema creation is transactional and marked with `PRAGMA user_version=1`. Reopening version 1 is a no-op; unknown versions and unversioned nonempty databases are rejected. Future migrations should be explicit, ordered transitions under the same transaction rather than silently recreating tables.

Saving the exact same run again is a no-op, verified by a canonical batch fingerprint. Reusing its UUID with different content is rejected. New runs of the same identities add associations and new observations without duplicating identities. Older collections cannot overwrite newer metadata. The same observation timestamp with different values is a conflict, not an implicit correction. Content metadata is latest-per-source, not a historical snapshot of each run's title/description; metric observations carry their own times.

## Retention and minimization

Persistence is **disabled without an explicit policy for the collecting source**. Policies require a positive finite `ttl`. `allow_live` defaults to false, and unknown provenance cannot be persisted. There are no built-in retention durations or permissions for Reddit, YouTube or any other live platform. An operator must resolve applicable provider requirements before explicitly enabling storage; `allow_live=True` is configuration, not evidence of legal permission.

```python
from datetime import timedelta
from pathlib import Path
from trendscout.ingestion.models import RetentionPolicy
from trendscout.ingestion.repository import IngestionRepository

# Illustrative duration for synthetic fixtures only; not a provider allowance.
policy = RetentionPolicy(source_id=source.source_id, ttl=timedelta(hours=2))
with IngestionRepository(Path("ingestion.sqlite3"), [policy]) as repository:
    repository.save(result)
    item = repository.get_item("synthetic", "fixture-1", source.source_id)
    deleted_counts = repository.purge_expired()
```

Content expiration is the earlier of collection time plus source TTL and the record's explicit source deadline. Observations use the earliest of observation time plus TTL, explicit metric deadline and content expiration. Associations expire with their collected record. A batch containing already-expired content or observations is rejected atomically, and future-completed runs cannot be saved. Replaying old data does not renew its original observation retention. A genuinely new collection can refresh latest metadata, while older observations/associations keep their individual deadlines. Config changes affect subsequent saves; existing stored deadlines are not automatically rewritten.

Expired data is hidden by reads even before cleanup. Call `purge_expired()` regularly: it deletes expired observations, associations and source metadata, then removes identities with no remaining source metadata. Other unexpired sources sharing an identity survive. Once a run has no retained associations, its content-derived retry fingerprint is cleared. Only its operational summary (source, provenance, times, status, limits/counts and safe error codes) remains; raw titles, IDs, metrics, queries and response bodies are not preserved in that summary. A purged nonempty run cannot be replayed under its old UUID.

Cleanup is explicit; no background scheduler is installed. SQLite row deletion is logical deletion, not guaranteed forensic erasure of database pages, filesystem copies or backups. Deployment-specific backup cleanup and any required secure erasure are outside this milestone. Operational summaries can also require an installation-specific deletion policy; do not infer indefinite provider permission from this foundation.

## Offline demonstration and tests

From the project root, with the existing editable installation:

```powershell
.\.venv\Scripts\python.exe -m trendscout.ingestion.demo
.\.venv\Scripts\python.exe -m pytest -q tests/ingestion
.\.venv\Scripts\python.exe -m pytest -q
```

The demonstration uses only synthetic records and a temporary SQLite file. It saves a batch, retries delivery, recollects the same identities, reads records/observations, expires the older observations and associations, then purges all source records. It confirms that two operational run summaries remain, and removes the disposable database on exit. Simulated clocks test expiry without sleeping; timestamps are not presented as collected history.

Tests cover model validation, UTC conversion, absent/negative metrics, adapter limits/errors, duplicates, replay conflicts, database reopening, SQL parameters, rollback, partial/failed results, opt-in persistence, per-source retention, source deadlines, foreign keys and transactional migration failure. Existing V1.2 tests remain unchanged.

## Next provider integration and limits

V1.3.2 can implement an authorized YouTube adapter against this contract, using video IDs, optional native counters, public attribution and verified retention configuration. A future Reddit ingestion adapter can independently normalize approved OAuth responses without changing the existing CLI adapter. Provider-specific exceptions such as signed scores need explicit modeling rather than coercion. Neither adapter is implemented here.

This milestone has no cross-platform scoring, historical trend estimates, automatic policy discovery, live credential configuration, generalized raw-payload storage, database dashboard, distributed collection, full-text search or content-metadata version history. The synthetic adapter does not use its query to claim relevance or discover real trends.
